Source-document downloads (`advisor.entrepreneurs.documents.show`, `portal.documents.show`, and client document downloads) remain evidence access, not certified-output routes. Preserve scan/ownership/visibility controls; do not store release outputs there in a way that bypasses release authorisation. No entrepreneur-specific public share route was found in the mapped route files. Any future sharing endpoint must serve a retained release artifact through the same authorisation contract. General report/proposal/template previews and the strategic-budget PDF are separate products.

Phase 1 introduces a common document context and server-side progression decision, including draft notices and an explicit list of unimplemented prerequisites. It cannot issue `Release-certified`. Phase 3 adds the atomic capture-render-check-store-finalise transaction and retained-byte downloads across all three documents. A fallback must never inherit the primary renderer's verification result; unverified output stays Draft.

Keep assessment finalisation, summary generation, internal rendering and external progression as distinct actions over that context. Preserve score/coherence prerequisites for an approved AI summary, but do not require external-release success merely to inspect a Draft. In particular, adapt the current brief `can_generate` preview restriction so an authorised advisor can inspect available content and findings while missing/unapproved summary content is visibly unavailable. Never manufacture an approved summary to unlock the preview or make a generated-document check a prerequisite for generating that document.

### DH-03 navigation performance correction

The entrepreneur detail payload evaluates document readiness. Comparing every pair of long plan sections with recursive `similar_text` made this read path vulnerable to the HTTP execution limit. A local profile using the supplied plan's extracted text took 35.938 seconds for DH-03 alone; the replacement took 1.138 seconds on the same input. These measurements isolate the rule and are not production request timings.

DH-03 now normalises case and whitespace once per block and compares full-text Unicode character-trigram multisets using Dice similarity (`200 * shared occurrences / total occurrences`). The configured similarity threshold remains 90 percent by default. Exact repeated headings and narrative still fail; short numeric cells remain exempt. Unlike the previous 4,000-character prefix comparison, differing content later in a block participates in the result. Fingerprint construction is linear in text length, with each pair comparison linear in the distinct trigrams; the number of block pairs remains quadratic. This is a duplicate-review heuristic, not semantic equivalence or release certification. Existing service dependency hashes invalidate decisions made against the old comparison code.

Regression coverage includes exact and near duplicates, Unicode, configured thresholds, unrelated text, differing long suffixes, a 51-block performance budget, and advisor detail requests through both Inertia and direct navigation. F1 expectations and Draft-only release behaviour remain unchanged.
